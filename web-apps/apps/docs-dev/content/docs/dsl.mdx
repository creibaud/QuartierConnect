## À quoi sert le DSL

Le DSL de QuartierConnect est un **micro-langage de requête** qui permet aux administrateurs d'interroger les collections MongoDB sans écrire de code. Il est exposé via `POST /dsl/query` et consommé depuis le panneau d'administration React.

Le choix d'un DSL plutôt que de MongoDB brut répond à trois objectifs :

- **Sécurité** : les requêtes MongoDB brutes peuvent exprimer des injections complexes.
- **Simplicité** : une syntaxe quasi en langage naturel, utilisable sans formation MongoDB.
- **Contrôle** : une liste blanche de collections et aucune opération destructive.

Techniquement, le composant `dsl/` est écrit en **Python** avec **PLY** (lexer + parser LALR(1)), et invoqué depuis NestJS via le pont **pythonia**.

## Syntaxe

### Verbes et mots réservés

Deux verbes seulement : `FIND` (renvoie des documents) et `COUNT` (renvoie un entier). Les mots réservés — `FIND`, `WHERE`, `AND`, `OR`, `LIMIT`, `COUNT`, `IN`, `LIKE` — sont **insensibles à la casse** : `find`, `FIND` et `Find` sont équivalents.

### Grammaire

```
query : FIND IDENTIFIER
      | FIND IDENTIFIER WHERE conditions
      | FIND IDENTIFIER LIMIT NUMBER
      | FIND IDENTIFIER WHERE conditions LIMIT NUMBER
      | COUNT IDENTIFIER
      | COUNT IDENTIFIER WHERE conditions

conditions : condition
           | conditions AND condition   → merge des filtres
           | conditions OR condition    → {'$or': [left, right]}

condition : IDENTIFIER EQ  value        → {field: value}
          | IDENTIFIER NEQ value        → {field: {'$ne': value}}
          | IDENTIFIER GT  value        → {field: {'$gt': value}}
          | IDENTIFIER GTE value        → {field: {'$gte': value}}
          | IDENTIFIER LT  value        → {field: {'$lt': value}}
          | IDENTIFIER LTE value        → {field: {'$lte': value}}
          | IDENTIFIER LIKE value       → {field: {'$regex': v, '$options': 'i'}}

value : STRING | NUMBER | IDENTIFIER
```

Les opérateurs de comparaison disponibles sont donc `=`, `!=`, `>`, `>=`, `<`, `<=` et `LIKE` (recherche insensible à la casse via `$regex`). Les valeurs sont des chaînes (`'open'`, `"Paris"`), des nombres (`42`, `3.14`) ou des identifiants. Les espaces, tabulations et retours à la ligne sont ignorés.

### Exemples

```
FIND incidents
→ db.incidents.find({})

FIND incidents LIMIT 5
→ db.incidents.find({}).limit(5)

COUNT incidents
→ db.incidents.countDocuments({})

FIND incidents WHERE status = 'open'
→ db.incidents.find({status: 'open'})

FIND services WHERE type = 'free' AND category = 'gardening'
→ db.services.find({type:'free', category:'gardening'})

FIND services WHERE type = 'free' OR type = 'exchange'
→ db.services.find({$or:[{type:'free'},{type:'exchange'}]})

FIND services WHERE title LIKE 'garden'
→ db.services.find({title:{$regex:'garden',$options:'i'}})

FIND events WHERE maxAttendees >= 50 LIMIT 10
→ db.events.find({maxAttendees:{$gte:50}}).limit(10)
```

## Comment une requête est exécutée

Le pipeline est linéaire, du texte au résultat JSON :

1. **Requête HTTP** — `DslController` reçoit le `POST /dsl/query`, protégé par `JwtAuthGuard` + `RolesGuard` avec `@Roles('admin')`. `DslService` valide d'abord la **longueur (≤ 500 caractères)**.
2. **Lexer** (`dsl/lexer.py`) — découpe le texte en tokens (`FIND`, `IDENTIFIER`, `WHERE`, `STRING`…).
3. **Parser** (`dsl/parser.py`) — grammaire **LALR(1)** produisant un AST sous forme de `dict` Python (`type`, `collection`, `filter`, `limit`).
4. **Compilateur** (`dsl/compiler.py`) — valide la collection contre une **liste blanche** et renvoie l'AST.
5. **Exécution** (`dsl/main.py`) — via **Motor** (MongoDB async) : `find()` pour un `find`, `count_documents()` pour un `count`.
6. **Retour** — le résultat JSON (liste de documents ou entier) remonte par pythonia jusqu'à NestJS, qui répond `200 { results: [...], count: N }`.

### AST généré

```python
# "FIND incidents WHERE status = 'open' LIMIT 10"
{
    'type': 'find',
    'collection': 'incidents',
    'filter': {'status': 'open'},
    'limit': 10,
}
```

### Exécution côté Python

```python
async def execute(query_string: str) -> list | int:
    ast = compile_query(query_string)
    if ast['type'] == 'find':
        cursor = db[ast['collection']].find(ast['filter'])
        if ast.get('limit'):
            cursor = cursor.limit(ast['limit'])
        return await cursor.to_list(length=1000)
    elif ast['type'] == 'count':
        return await db[ast['collection']].count_documents(ast['filter'])
```

## Sécurité et garde-fous

| Vecteur | Mitigation |
|---------|-----------|
| Collections arbitraires | Liste blanche stricte : `incidents`, `neighborhoods`, `services`, `events`, `users` |
| Opérations destructives | `FIND` et `COUNT` uniquement — aucun `DELETE`/`UPDATE`/`INSERT` |
| Injections MongoDB | Les valeurs passent par le moteur — aucune concaténation |
| Accès non autorisé | Route protégée par `@Roles('admin')` |
| Ressources excessives | `limit(1000)` maximum par requête |

## Erreurs courantes

| Erreur | Cause | Message |
|--------|-------|---------|
| `SyntaxError` | Token illégal (`FIND !@#`) | `Illegal character '!' at position 5` |
| `SyntaxError` | Grammaire invalide (`FIND WHERE incidents`) | `Syntax error at 'WHERE'` |
| `SyntaxError` | Fin prématurée (`FIND incidents WHERE`) | `Unexpected end of input` |
| `ValueError` | Collection non autorisée (`FIND passwords`) | `Unknown collection 'passwords'. Allowed: ...` |

> Une collection hors liste blanche est rejetée par le compilateur avant tout accès à la base : la requête n'atteint jamais MongoDB.
